# deploy/pi — set up a fresh Reachy Mini from this repo

**Moving from an existing robot? Follow [TRANSFER.md](TRANSFER.md)** (push +
encrypted secrets bundle + install + verify). Everything the deployed robot
needs, minus secrets. Branch
`pi/deployment-snapshots` is always the newest state; every
`snapshot/YYYY-MM-DD-HHMM` branch is a frozen restore point.

## New robot in 5 steps

```bash
# 1. get the code (user "pollen" on the Reachy Mini image; path is assumed by the units)
git clone -b pi/deployment-snapshots https://github.com/Supervaise-Inc/CJAP.git \
    ~/Supervaise-Reachy-Mini-Project-main
cd ~/Supervaise-Reachy-Mini-Project-main

# 2. install everything (apt, venv, models, clips, dotfiles, dashboard, systemd)
bash deploy/pi/install.sh            # ~10-15 min on a CM4, needs internet + sudo

# 3. paste the keys
nano app/.env                        # ANTHROPIC_API_KEY, OPENAI_API_KEY, ELEVEN_API_KEY

# 4. reboot once (PipeWire realtime limits), then check
sudo reboot
verify.sh                            # 23 PASS/FAIL checks; services start at boot
#    http://reachy-mini.local:8080          troubleshooting dashboard
#    http://reachy-mini.local:8080/maintain?key=cjap
#    http://reachy-mini.local:8080/audience  /avatar  /event

# 5. (optional, ElevenLabs credits) pre-warm the ~150 canned/event answers
app/.venv/bin/python scripts/prerender_canned.py
```

Say **"Hey Cee-Jap"** → the robot listens → ask a question.

## What is in here

| Path | Installs to | Notes |
|---|---|---|
| `requirements-pi.txt` | `app/.venv` | exact `pip freeze` of the live venv (Py 3.13, aarch64); installed `--no-deps` |
| `audio/fillers/` (40) | `~/fillers` | thinking-aloud clips, accent voice |
| `audio/fillers_ack/` (3) | `~/fillers_ack` | sub-second "Ah." acknowledgments |
| `audio/fillers_bail/` (4) | `~/fillers_bail` | not-connected / be-specific / enroll prompts — must exist offline |
| `audio/demo_clips/` | `~/demo_clips` | Tagalog pronunciation sample (dashboard button) |
| `dotfiles/` | `~/.asoundrc`, `~/.asoundrc.route`, `~/bin/audio-out`, `~/speaker-watchdog.sh` | audio routing: internal XMOS via PipeWire, BT via BlueALSA |
| `dotfiles/config/` | `~/.config/pipewire/*.conf.d`, `~/.config/systemd/user/*.service.d/rt.conf` | PipeWire quantum + realtime tuning (the 2026-07-21 choppy-audio fix) |
| `systemd/user@.service.d/` | `/etc/systemd/system/user@.service.d/` | RT/nice limits for the user session (same fix; needs one reboot) |
| `dashboard/` | `~/pi_dashboard/` | stdlib web UI (:8080 http, :8443 https self-signed) |
| `systemd/` | `/etc/systemd/system/` | `supervaise` (robot), `pi-dashboard`, `wifi-fallback`, `speaker-watchdog` (installed, not enabled) |
| `systemd/supervaise.service.d/wakeword.conf` | drop-in | ALL runtime feature flags + thresholds — the tuning lives here |
| `tools/` | `~/bin/` | `snapshot-push.sh` (live robot → repo), `export-private.sh` / `import-private.sh` (encrypted secrets bundle), `verify.sh` (health check), wav generators |
| `PROJECT_NOTES.txt` | — | plain-text team notes (served at `/notes`) |

Wake-word model: `app/wake/models/hi_see_jap.onnx` (in the repo; selected by
`CJ_WAKE_OWW_MODEL_PATH` in `wakeword.conf`).
Speaker-ID model: downloaded by `install.sh` from the sherpa-onnx releases.
Entity dictionary / canned answers / pronunciation lexicon: `data/entities/`.

## Deliberately NOT in the repo (public)

- `app/.env`, `voice/config.py` — API keys. Templates: `app/.env.example`, `voice/config.example.py`.
- `~/.voice_cache/` (300 MB of ElevenLabs clips + word alignments) — regenerates on use; `prerender_canned.py` warms the curated set.
- `~/pi_dashboard/certs/` — regenerated by `install.sh`.
- `~/pi_dashboard/assets/liveavatar.json` — HeyGen key; add by hand for `/avatar`.
- `~/speaker_id/enrolled.npz` — a person's voice print; enroll from the dashboard.

All of these travel in ONE encrypted file: `export-private.sh` on the old
robot → `import-private.sh` on the new one (see TRANSFER.md).
- Bluetooth pairings — pair via the dashboard BT card; `audio-out sony|marshall` are hard-wired to the reference robot's speakers' MACs.

## Updating an existing robot

```bash
cd ~/Supervaise-Reachy-Mini-Project-main && git pull && bash deploy/pi/install.sh
sudo systemctl restart supervaise pi-dashboard
```
`install.sh` is idempotent: it never overwrites `.env`, `config.py`, `.asoundrc.route`, certs, or clips already present.

## Pushing changes from the robot

`snapshot-push.sh` (in `~/bin` on the reference robot) syncs the live
checkout + dashboard + units + dotfiles + clip pools + a fresh
`requirements-pi.txt` into this repo, commits on `pi/deployment-snapshots`,
tags a `snapshot/<ts>` branch and pushes both to remote `neto`.
